# 자연순위 분석용 복사 운영 지침

1. **기존 잔여량 확인 → 예상 증가량 계산 → 사용량 제한 설계 → 구현** 순서를 홈페이지 기능 추가마다 고정한다.

## 기능 계약

- `/admin/place-monitor`의 `똑순이 분석용 복사`는 현재 브라우저 메모리에 있는 최신 센서 요약과 사용자가 이미 불러온 이력만 사용한다.
- 버튼 클릭은 새 검색, 서버 분석, DB 조회·저장, AI 호출, 파일 업로드, 페이지 새로고침을 실행하지 않는다.
- 질문은 서버로 보내거나 로그에 남기지 않는다.
- 성공 표시는 `navigator.clipboard.writeText` 완료 뒤에만 보여 준다. 실패하면 같은 전문을 읽기 전용 텍스트 영역에 표시한다.
- 클립보드·브라우저 동작 외의 클릭당 추가 사용량은 DB 조회 0회, DB 저장 0회, 서버 요청 0회다.

## 데이터 해석과 범위

- 없는 데이터는 추정하지 않고 `미수신`, `미확인`, `미연결`로 적는다.
- 최신 센서 요약과 사용자가 불러온 최대 50건을 전체 검색 결과나 최근 30일 전체 자료로 확대하지 않는다.
- 동일한 measurement ID는 전문에서 한 번만 집계한다.
- 마지막 시도와 마지막 정상 측정을 분리하고, 실패·보류·오래된 정상을 오늘 정상 순위로 바꾸지 않는다.
- 발견 상태는 `발견`, `확인 범위 내 미발견`, `확인 불가`로 분리하고 원본 판독 상태를 함께 보존한다.
- 최근 50건에서 D3가 보이지 않는 것만으로 전체 누락을 확정하지 않는다. 수신된 D3는 측정시각과 동기화시각을 분리해 표시한다.
- 관측기가 보고한 예정 작업과 실제 실행 트리거 등록 확인을 구분하고, 트리거 자료가 없으면 `미수신`으로 표시한다.
- `AMBIGUOUS_ENTITY`, `NOT_IN_OBSERVED_RANGE`, 0건, `COMPLETED`, 서로 다른 검색조건, 재판독, 중첩 변경의 제한을 전문에 유지한다.
- 원본 객체를 직렬화하지 않는다. 허용된 요약 필드와 비정밀 검색조건만 선택한다.

## 변경과 검증

- 새 대형 라이브러리나 외부 서비스를 추가하지 않는다.
- 기존 가시 탭 15분 조회 주기와 관리자 인증을 유지한다.
- 운영 반영 전 단위 테스트, 변경 파일 lint, production build를 실행한다.
- 브라우저 검증에서는 클릭 시 발생한 요청과 기존 예약 조회가 우연히 겹친 경우를 구분한다.
- 운영 적용은 Preview/Production 배포와 별도 승인 대상으로 취급한다.
